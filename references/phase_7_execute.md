# Phase 7: Specify & Execute

**Goal**: To create the detailed Product Requirements Document (PRD) and the technical Business Requirements Document (BRD) or High-Level Design (HLD) that will guide the execution phase.

**Owners**: The **Product Specialist (PS)** is responsible for creating the PRD. The **Tech Lead (TL)** is responsible for the BRD/HLD.

## Key Steps

### 7.1: Write the Product Requirements Document (PRD)
The Product Specialist is responsible for writing the PRD, which serves as the single source of truth for the feature. The PRD should include:

- **User Stories**: Detailed descriptions of the feature from the user's perspective.
- **Acceptance Criteria**: The conditions that must be met for a user story to be considered complete.
- **Scope**: A clear definition of what is in and out of scope for the release.
- **Success Metrics**: The metrics that will be used to measure the success of the feature, as defined in Phase 4.

### 7.2: Write the Business Requirements Document (BRD) / High-Level Design (HLD)
The Tech Lead is responsible for writing the BRD or HLD, which outlines the technical implementation plan. This document should include:

- **Technical Architecture**: A diagram and description of the technical approach.
- **Data Model**: Any changes to the database schema.
- **API Contracts**: The specifications for any new or modified APIs.
- **Technical Risks**: Any remaining technical risks and a plan to mitigate them.

### 7.3: Execute
With the PRD and BRD/HLD complete, the development team can begin building the feature. The Product Specialist and Tech Lead should remain actively involved throughout the development process to answer questions, clarify requirements, and ensure that the final product meets the goals of the feature request.

## Phase 7 Checkpoint (Execution)

This phase is complete when the feature has been developed, tested, and is ready for release.

**Output**: The final **PRD** and **BRD/HLD** documents, and ultimately, the shipped feature.
